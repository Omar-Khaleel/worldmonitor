# عين الصقر — محطة البث والتحكم المباشر

يحتوي المشروع على تطبيقين منفصلين فعلياً:

- **غرفة التحكم:** تطبيق الإدارة الكامل في `/control/`.
- **شاشة المشاهد:** عارض خفيف ومستقل في `/broadcast/`، لا يستورد تطبيق الإدارة أو مكوّناته.

هذا الفصل يتم على مستوى ملفات HTML ومداخل JavaScript والتوجيه، وليس عبر CSS أو باراميتر فقط. لذلك فإن إعادة تحميل صفحة المشاهد تبقي المستخدم داخل شاشة المشاهد ولا تعيده إلى الإدارة.

## التشغيل المحلي

```bash
git checkout broadcast-station-mvp
npm install
npm run dev -- --host 0.0.0.0
```

غرفة التحكم:

```text
http://localhost:3000/control/
```

شاشة المشاهد:

```text
http://localhost:3000/broadcast/
```

الرابط الحي الثابت الذي يظهر في غرفة التحكم يكون بالشكل الآتي:

```text
http://localhost:3000/broadcast/?station=ayn-xxxxxxxxxxxx&lang=ar
```

يجب استخدام الرابط الذي يحمل `station` في OBS أو جهاز المشاهد. لا يتغير هذا الرابط عند تعديل القنوات أو اللوحات.

## الفصل الكامل بين الإدارة والمشاهد

### غرفة التحكم

`control/index.html` يحمل `src/control-entry.ts`، والذي يشغّل تطبيق الإدارة الكامل ثم ناشر البث الخفيف.

### شاشة المشاهد

`broadcast/index.html` يحمل `src/broadcast-viewer-entry.ts` فقط. العارض لا ينشئ `App` ولا يحمل:

- لوحة الإدارة.
- إضافة اللوحات والخانات.
- الإعدادات والتبويبات.
- مقابض تغيير الحجم.
- قوائم القنوات والكاميرات.
- مكوّنات التحليل الثقيلة الخاصة بالإدارة.

غرفة التحكم ترسل إلى العارض إسقاطاً خفيفاً يحتوي على النصوص المختارة، عناوين الشريط، مصادر الفيديو، التخطيط، وطبقات الخريطة.

## التحديث المباشر

كل تغيير في غرفة التحكم يُنشر تلقائياً، ثم يصل إلى شاشة المشاهد من دون إعادة تحميل.

وسائل المزامنة:

1. `BroadcastChannel` بين تبويبات المتصفح نفسه.
2. أحداث `localStorage` كمسار احتياطي محلي.
3. `GET/PUT /api/broadcast/state` بين الأجهزة، مع فحص كل ثانية.
4. إعادة فحص فورية عند عودة التركيز إلى التبويب أو ظهور الصفحة مجدداً.

خادم Vite المحلي يشغّل مساري الحالة والترجمة عبر Plugin خاص، لذلك تعمل المزامنة والترجمة أثناء التطوير المحلي أيضاً.

## تخزين الحالة بين أجهزة ونسخ Serverless متعددة

عند توفر متغيري Upstash التاليين، تُحفظ حالة المحطة في Redis لمدة سبعة أيام وتتشاركها جميع نسخ الخادم:

```text
UPSTASH_REDIS_REST_URL=...
UPSTASH_REDIS_REST_TOKEN=...
```

يستخدم النظام مفاتيح منفصلة للحالة والمالك والإصدار. ملكية المحطة تُحجز ذرياً بواسطة `SET NX` باستخدام بصمة مفتاح التحكم، لذلك لا يستطيع مفتاح مختلف الكتابة فوق محطة قائمة.

عند غياب Upstash، يستخدم التشغيل المحلي ذاكرة العملية. هذا مناسب لجهاز تطوير واحد، لكنه ليس تخزيناً دائماً بين نسخ Serverless.

## أداء شاشة المشاهد

العارض الخفيف يتبع القواعد الآتية:

- لا يحمل تطبيق الإدارة.
- لا يحمل HLS إلا عند وجود قناة HLS مختارة.
- لا يحمل الخريطة إلا بعد ظهور هيكل الصفحة والأخبار.
- يستخدم `/embed.html` للخريطة بدلاً من تحميل نظام الخريطة داخل العارض نفسه.
- يعيد بناء مصادر الفيديو فقط عندما تتغير قائمة المصادر.
- يتجاهل نتائج تحميل فيديو قديمة إذا وصل تحديث أحدث أثناء التحميل.
- لا يبدأ طلبات RSS الاحتياطية عندما تكون أخبار غرفة التحكم حديثة وكافية.

## التحكم من غرفة التحكم

غرفة التحكم تدير:

- اللوحات ومصادر API المعروضة.
- القنوات التلفزيونية المباشرة.
- كاميرات الويب.
- طبقات الخريطة.
- عدد أعمدة البيانات.
- عدد أعمدة جدار الفيديو.
- المسافات بين العناصر.
- إظهار أو إخفاء الخريطة.
- الشريط وعدد أخباره وسرعته.
- مصدر الترجمة والنموذج.
- اسم القناة ووصفها.

عند تغيير أي خيار، تُرسل الإعدادات سريعاً، ثم ينشر ناشر الإسقاط نسخة النصوص والأخبار ومصادر الفيديو المناسبة للمشاهد.

## الشريط الإخباري العربي

الشريط يحصل أولاً على الأخبار التي تجمعها غرفة التحكم من جميع اللوحات المحملة، بما فيها اللوحات غير المعروضة بصرياً للمشاهد.

يعطي الناشر أولوية إلى:

- السياسة والأخبار العالمية والإقليمية.
- الصراعات والأزمات والأمن والعقوبات.
- الاستخبارات والتحليل والمخاطر.
- الاقتصاد والطاقة والأسواق والتقنية.

ثم يقوم بما يأتي:

- إزالة الأخبار المكررة.
- عرض الأخبار العربية فوراً.
- نشر النص الأصلي فوراً كي لا يبقى الشريط فارغاً.
- ترجمة النصوص الإنجليزية على دفعات محدودة.
- نشر النسخة المترجمة عند اكتمالها.
- تخزين الترجمات مؤقتاً.

عندما تكون أخبار غرفة التحكم أقل من الحد المطلوب أو أقدم من دقيقتين، يستخدم العارض مصادر RSS احتياطية بعد مهلة قصيرة. يعاد فحص هذه المصادر كل 90 ثانية، ولا تُحمّل عندما تكون الأخبار المرسلة من غرفة التحكم حديثة وكافية.

سلسلة الترجمة:

1. المصدر المختار في غرفة التحكم.
2. خادم `/api/broadcast/translate`.
3. Ollama المحلي كمسار احتياطي عند السماح به.
4. النص الأصلي إذا تعذرت جميع خدمات الترجمة، بدلاً من شريط فارغ.

## الترجمة عبر Ollama

من غرفة التحكم:

```text
مصدر الترجمة: Ollama محلي
عنوان Ollama: http://127.0.0.1:11434
النموذج: qwen2.5:7b
```

على Windows:

```powershell
setx OLLAMA_ORIGINS "http://localhost:3000"
ollama pull qwen2.5:7b
taskkill /F /IM ollama.exe
ollama serve
```

## خادم الترجمة المركزي

واجهة الترجمة:

```text
POST /api/broadcast/translate
```

متغيرات مزود متوافق مع OpenAI Chat Completions:

```text
BROADCAST_TRANSLATION_BASE_URL=https://provider.example/v1
BROADCAST_TRANSLATION_API_KEY=secret
BROADCAST_TRANSLATION_MODEL=model-name
```

## OBS

استخدم رابط المحطة الذي يحمل `station` في Browser Source:

```text
Width: 1920
Height: 1080
FPS: 30
Shutdown source when not visible: Off
Refresh browser when scene becomes active: Off
```

لا يحتاج المشهد إلى Refresh عند كل تعديل؛ التحديث يصل مباشرة.

## التوجيه ومنع الرجوع إلى الإدارة

في Vite توجد مدخلات بناء مستقلة لـ:

```text
control/index.html
broadcast/index.html
```

وفي Vercel توجد Rewrites مستقلة للمسارين، كما يُستثني Catch-all هذين المسارين من التحويل إلى `dashboard.html`.

ويُستثنى `/control/` و`/broadcast/` من كاش تنقل Service Worker، مع ترويسات `no-store` على النشر. هذا يمنع إعادة استخدام نسخة الإدارة القديمة عند Refresh.

## الفحوص

Workflow محطة البث يتحقق من:

- TypeScript للواجهة وAPI.
- Biome.
- عقد API وسياسات Rate Limit.
- اختبارات ملكية الحالة وPUT/GET والفحص الشرطي `after`.
- استقلال ملفات ومداخل `/control/` و`/broadcast/`.
- بناء Vite الإنتاجي.
- وجود ملفي HTML منفصلين بعد البناء.
- عدم تحميل ملف الإدارة داخل المشاهد.
- حد أعلى لحجم ملفات المشاهد الأولية.
- Smoke test حقيقي لمسارات Refresh وAPI على Vite.
- اختبار Playwright يثبت وصول تعديل ثانٍ من دون Reload، ثم يثبت بقاء الصفحة شاشة مشاهد بعد Refresh.

أوامر الفحص الأساسية:

```bash
npm run typecheck
npm run typecheck:api
npx vite build
npx tsx --test tests/broadcast-route-separation.test.mts tests/broadcast-state.test.mts
npx playwright test e2e/broadcast-station.spec.ts --project=chromium
```
